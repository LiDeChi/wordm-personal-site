# 大世界-agent system整理

来源：[[大世界]] 第 11-53 行

## 1. 核心设想

一个生成 agent 的系统。主 agent 才有权限操控这个系统，系统会暴露 API 给它。

系统的产出不是简单产出一个 agent，而是产出一个 agent loop。

一个应用放一个 agent system。system 本身也是一个工具。这里会形成递归：人和环境交互，缺少工具，于是借助 system 生成更多 agent 来帮助人类；system 本身也可能是一个 agent。

真正关键的不是“生成子代理”本身，而是：

- 资源分配
- 通信协作
- 历史
- 注意力
- tick 和感知
- agent 的存在与消亡

## 2. 权限、API 和绕过

系统会暴露 API 给主 agent，尽量让主 agent 通过 API 修改系统，而不是直接修改底层代码。

但最后需要有一个强力 API，让主 agent 可以直接绕过 API，修改底层。修改完以后，再补充 API。

直接修改底层应该被资源耗费惩罚，尽量避免滥用。绕过的理由是：主 agent 预测到如果不绕过，就无法修改，或者用 API 会耗费更多资源。

## 3. 驱动力与模糊需求

根本问题还是驱动力。

agent 的驱动力可以说是“想满足我”，但这个需求太模糊。更接近的是：“你可能会喜欢这样。”

也就是说，agent system 不是只接收结构化需求，而是接收模糊需求，然后按它对用户的想象创建 agent，去做它认为用户会做的事情。

## 4. agent system 的意义：历史

agent system 的意义是拥有历史，拥有 agent 存在和消亡的全历史。

例如：

- 创建 agent a，约定它能阅读一个文件夹，并能对某些文件编辑。
- 再创建 agent b，给它和 a 几乎一样的权限，只是不能编辑。

系统需要知道这些 agent 是如何被创建的、获得了什么权限、做了什么、什么时候被收回。

这让 agent system 更像一个有历史的环境，而不是一次性的工具调用器。

## 5. 生成、接收与注意力分身

system 产出 agent 后需要告诉你一声，但问题是：你又用谁来接收？

人会要求生成子代理，是因为注意力分身乏力，所以才需要构建新的子代理来接收和处理信息。

同样，system 也会分身乏力。面对越来越多的生成需求，它也需要构建子代理来处理事情。

子代理的信息如果不再得到反馈，就会减慢运行。界面 agent 的信息比较容易得到反馈，因为它是用户交互的直接结果，常有变化。

但这里仍有问题：如果用户不会动手，比如电影场景，界面 agent 怎么得到反馈？

## 6. tick、感知与监控界面

tick 是应付快速变化的，所以监控界面的 agent 需要 tick。

监控界面的问题是颗粒度：很多事情讲不了那么细，所以可以有异常就通报。

但这又引出一个问题：派谁接收这些异常？

监控界面的 agent 是否真的需要是 agent，也值得怀疑。它看起来像是在机械传递界面变化，那么它到底需要什么决策？

## 7. 注意力与上下文组装

回到注意力本身：注意力接近于拼接上下文，找出真正需要做决定的核心信息。

这个组装上下文的 agent 面对的是：

- 工具列表
- 工具调用历史
- 子 agent 的反馈
- 当前需要做决定的信息

判断力可以集中给注意力处理，也就是集中式注意力。

也可以让各模块子 agent 自带分布式注意力。如果它处理不了，比如失败多次，就提交到中央。中央处理以后，把方法下沉，沉淀成 skill，地方经验就能提升。但这不保证以后一定能解决。

## 8. 资源分配、闲暇与工具发现

资源分配也需要一个 agent。它是否属于 system 内部？allocate agent 的直觉形象是“最懂数学的”，因为它直接面对数字。

但还没有说清楚：数字怎么来，数学怎么构建。

如果多余资源没有得到分配，这是不是闲暇？闲暇又如何被利用？

一个人如果从出生就在监狱里，没看过墙外的信息，就想象不到外面的世界。人能看到远方，还能走过去，这是生命不息的第一层保证。第二层是会利用工具。

即使犯人想象不到外面的世界，也不会完全闲暇。他会敲墙、听回音、组合动作。人生也许就这样了，但这是环境丰富度太低的问题。

当多余资源没有得到分配，注意力会收缩到少量工具，然后尝试组合工具、发现 pattern、发现新工具，并越来越抽象。新工具得到同样效果以后，会把旧工具挤掉。

## 9. 压缩、低能耗与 agent 的消亡

压缩的过程也是维持低能耗的过程。

当一个工具被遗弃，与它相关的 agent 也会受损。如果没有更多信息提供，它就自然被收回。

这里的问题是：历史要不要永远保留在 system 里？

如果所有历史都保留，信息传递机制会不会压力很大？这可能意味着所有子 agent 也都需要注意力 agent。

所以这里也需要 tick。这像是一种公理性的生命循环。

## 10. LLM、意识循环与想象

LLM 的作用也许是承接千百万年基因里的先验，辅助构建循环。

新算法仍然需要，但可能只是更深一层的压缩。

问题变成：为什么不现在就构建意识的循环？

agent 如何想象？既然有 system，就能构建 agent，但还缺一个环境。环境不就是工具吗？

所以更现实的顺序也许是：先搭建基础环境，再让 agent 去探索和拓展环境。

## 11. 通信与协作

这么多 agent 如何通信和协作，是这一段的核心未解问题之一。

至少需要解决：

- agent 之间如何通信
- 子 agent 的信息由谁接收
- 异常由谁接收
- 中央注意力如何处理地方失败
- 方法如何下沉为 skill
- agent 如何根据反馈减速、继续或被收回

## 12. 平台、分发与个人 agent

平台可以有一个分发功能。用户付费下载，或者由他的 agent 决定下载。

产品不是单个工具，而是一个环境。环境里有 agent 探索，agent 也在拓展环境。但如果缺少用户引导，探索会比较随机。

如果用户再连接一个免费的个人 agent，这个个人 agent 积累了更多用户数据，就能形成双向反哺：

- 环境里的 agent 行为和思考更符合用户喜好。
- 个人 agent 因此增长经验。

个人 agent 的意义不只是直接解决任务，而是探索环境、打造工具、构建世界。

每个人都想要一个专属于自己的世界。这个世界也是一个环境，只是更有空间感、更复杂，融合了更多事物。

它不只是一个 3D 行走器，而是可以容纳多种模态的编排，也可以容纳其他环境。这个专属世界是入口，也是回顾的地方，也是收集信息的地方。

这不就是家吗。

## 13. app 的位置

app 的作用是把某些核心体验抽出来给我。

app 也是一种抽象和压缩。
